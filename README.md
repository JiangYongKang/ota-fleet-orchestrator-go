# OTA Fleet Orchestrator（本地模拟版）

本地可运行的设备编队固件升级编排能力：用本地数据模拟设备端与云端交互，
使设备的**在线状态、期望配置与升级进度**在并发、乱序和重启场景下保持
一致且可解释。仅依赖 Go 标准库，无需任何外部服务。

## 快速开始

```bash
go run ./cmd/demo        # 端到端模拟：注册→乱序心跳→灰度→上报→超时回滚→重启恢复
go test ./...            # 全部单元测试（可重复运行）
go test -race ./...      # 含竞态检测
go test -v ./internal/rollout/   # 查看每个场景的输入与判定依据日志
```

要求 Go 1.25+（仓库在 Go 1.26 上验证）。

## 能力一览

- **注册 / 心跳 / 影子**：期望（desired）与上报（reported）分离记录并可判定
  收敛；重复注册幂等不覆盖；按心跳 seq 拒绝乱序旧心跳（不回退状态）、
  忽略重复心跳；离线（`heartbeat-timeout`）与恢复上线（`heartbeat-recovered`）
  原因可区分。
- **分批灰度**：按设备组、按设备 ID 确定排序分批；同一设备同一时刻至多一个
  在途升级；逐设备做版本合法性检查，拒绝降级/原地升级/跨大版本/跨多个次版本；
  单台设备在途或回滚受阻不阻塞其它设备。
- **结果 / 超时 / 回滚**：重复与迟到的结果上报幂等忽略、不重复计数；部分成功
  可逐设备定位；超过 `JobTimeout` 的中间态任务收敛为失败并回滚到原版本。
- **重启恢复**：状态原子落盘；重启后在途任务恢复但**不重复下发**，瞬态失败
  任务继续回滚，终态任务不重放。

## 代码布局

```
internal/version/   版本号解析、比较与升级合法性
internal/device/    设备档案、设备影子、心跳状态机、离线巡检
internal/store/     JSON 快照原子持久化（临时文件 + fsync + rename）
internal/rollout/   灰度计划、任务状态机、超时收敛、回滚、重启恢复
cmd/demo/          本地端到端演示（状态文件 ./demo-data/state.json）
docs/design.md     状态模型 / 版本兼容 / 灰度回滚策略 / 验证方法的详细说明
```

## 版本规则速查

`MAJOR.MINOR.PATCH`，同 MAJOR 下 MINOR 最多跨 1，同 MINOR 内 PATCH 自由前推；
拒绝降级、原地升级与跨 MAJOR。例：

| from → to | 结论 |
| --- | --- |
| `1.0.5 → 1.1.0` | 允许（跨一个次版本） |
| `1.2.0 → 1.2.9` | 允许（补丁） |
| `1.0.0 → 1.2.0` | 拒绝（跨多个次版本） |
| `1.1.0 → 2.0.0` | 拒绝（跨大版本） |
| `1.3.0 → 1.2.0` | 拒绝（降级） |

完整状态机、灰度/回滚与持久化语义见 [docs/design.md](docs/design.md)。
